**Deviation from the spec**: there are **two** `lifecycle` endpoints, not the single core one in spec section 1. Core `overtime/clients/{id}/lifecycle/` answers delete blockers; onboarding `onboarding/clients/{id}/lifecycle/` answers purge blockers (`can_purge`, `folders`, `documents`, `latest_export`) and owns `purge/`. Kept deliberately: purge rules never enter core, so core stays plugin-free. `cascade_counts` in the core payload covers onboarding rows through the hook.
**Also corrected**: `run_scheduler` lives at `apps/plugins/management/commands/`, not `core/management/commands/` (year-close plan Y1).
**Primary goal**: An admin can retire a client without ever losing overtime, payroll evidence or onboarding files, and a superuser can export and clean up onboarding data safely.
