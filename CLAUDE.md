## Universal Safety Rules

- Do not bypass security checks, migrations, hooks, or tests.
- Never commit or push unless explicitly requested.
- Do not scan unrelated documentation, generated files, logs, node_modules, venv, or .git.
- Load the routed context file (Task Router below) before coding and check its invariants — do not reapply fixes already documented as complete.
- Use TDD for implementation and bug fixes (write/update targeted test -> fail -> implement -> pass).
- **Migrate the dev DB after any model/migration change.** `db.sqlite3` is not migrated automatically. After pulling, switching branches, or touching a model, run `python manage.py migrate` and confirm `showmigrations <app>` has no `[ ]`. A runtime `OperationalError: no such column: <table>.<col>` means an unapplied migration, not a code bug. Check `showmigrations` before debugging the code.

## Minimal Code & YAGNI Execution Ladder

Before writing or modifying any code, follow this mandatory 7-step ladder:

1. **YAGNI Gate:** Ask "Is this feature or abstraction explicitly requested?" If not, do not build it.
2. **Reuse First:** Search the codebase for existing utilities, UI components, serializers, or services before creating new ones.
3. **Standard Library:** Prefer native Python standard libraries or built-in JavaScript/React features over custom helper functions.
4. **Existing Dependencies:** Use packages already present in `requirements.txt` or `package.json`. Do not introduce new packages without permission.
5. **Smallest Viable Diff:** Choose the smallest clean change (e.g., single-line fix or minor function edit) over multi-file refactoring.
6. **Zero Speculative Code:** No placeholder methods, unused parameters, unneeded catch blocks, or "future-proofing."
7. **Verify & Validate:** Run targeted tests to verify the minimal change before completing the task.

## Terminal Hygiene & Output Bounding

- **Quiet Flags:** Always run terminal commands with quiet/concise flags (`pip install -q`, `npm install --silent`, `python -m ruff check --output-format=concise`).
- **Targeted Reads:** Use bounded output (`head`, `tail`, `git diff --stat`, or targeted `grep`) instead of dumping raw log files or huge terminal outputs into the context window.
- **Excluded Paths:** Exclude `node_modules/`, `venv/`, `.git/`, generated bundles, logs, and `.devin/tracking/` archives from broad searches unless explicitly requested.
- **Execution Strategy:** Run only targeted unit tests while iterating; run the full verification suite exactly once at the end of implementation.

## Hot Invariants

- **A plugin missing for EVERY role = it failed to import, not permissions (2026-10-07)** — `discover_plugins()` skips a plugin whose module raises (usually a `requirements.txt` entry the running venv never installed: `xlsxwriter`, then `pypdf` for `tl_scorecard`, which hid the HBPR Workspace + TL scorecard links). It is now recorded in `plugin_registry.load_errors` and surfaced as system check `plugins.E001` (`apps/plugins/checks.py`), so `runserver`/`migrate`/`test` refuse to start quietly. After pulling any commit that touches `requirements.txt`, run `pip install -r requirements.txt` in the venv that serves the app, then restart runserver. Probe with that venv's interpreter, not `py -3.14`.
- **"Plugin pages won't open" is usually Vite, not Django (2026-10-04)** — `504 (Outdated Optimize Dep)` / `Failed to fetch dynamically imported module` means the dev server's dep optimizer went stale (a dep imported only from a lazy chunk or `import()` was discovered mid-session, or the lockfile changed under a running server). Triage first: `curl 127.0.0.1:5173/api/plugins/<name>/` (401 = backend fine) + `manage.py check`, then hard-reload / `npx vite --force`. A dep reachable only through lazy/dynamic imports must be listed in `optimizeDeps.include` in `frontend/vite.config.ts` (currently `dompurify`, `jspdf`, `html2canvas-pro`). See `03-FRONTEND-PATTERNS.md` §17.
- **Production admin routing** — Django's built-in admin lives at `/django-admin/` (since 2026-10-24); `/admin/*` belongs to the React admin panel (SPA fallback), so never proxy `/admin` to the backend or mount Django's admin there (nginx sent every refresh/deep link of the custom admin to Django's admin; pinned by `config/test_deployment.py`). `/django-admin/`, `/static/`, and the rate-limited `/django-admin/login/` are proxied to the backend in `frontend/docker/nginx.conf.template` (fixed 2026-09-27 — none of the three existed before, so admin silently fell through to the SPA and was completely unreachable in production despite docs claiming otherwise). The file is a `.template` now, not a static `.conf` — nginx's built-in envsubst-on-templates entrypoint renders it at container start so `${ONLYOFFICE_ORIGIN}` (CSP allowlist for the OnlyOffice document editor, empty/no-op if unset) can be substituted from a real env var. CSP is enforcing (flipped from report-only). Before editing this file: it still has plenty of native `$lowercase` nginx variables (`$host`, `$remote_addr`, `$trusted_ingress`, etc.) — envsubst only touches names that match an actual (conventionally-uppercase) container env var, so don't rename a new env var to something that collides with an nginx variable name.
- **Heavy feature libs need a dynamic import, not just a lazy-loaded page** — route-level `React.lazy` (done for every page since 2026-09-10) doesn't defer a *statically*-imported heavy dependency inside that page; it still ships in the page's own chunk graph and loads on page visit, not on use. Real case: `EngagementVisualizationPage.tsx`/`TLScorecardVisualizationPage.tsx` statically imported `captureChartsToPdf` from `pdfExport.ts` (html2canvas+jspdf, 663KB — the single largest chunk in the app), so visiting either page ate that cost even without clicking "Export PDF". Fixed 2026-09-27: `await import(".../pdfExport")` inside the click handler itself. Check bundle composition with `ANALYZE=true npm run build` (writes `dist/bundle-stats.html` via `rollup-plugin-visualizer`, gated off by default) before assuming a route-lazy page is fully deferred.
- **Payroll access and drafts** — (1) *Scope is decided at the run level and re-applied at the line level.* Only staff, superusers and `profile.is_hr` are company-wide (`_allowed_payroll_user_ids` returns `None`); the `manage` grant alone unlocks nothing, so any other holder is scoped to self + team, `GET /api/plugins/payroll/runs/scope/` returns `run_scope: company|team` (one helper) and the UI hides whole-run actions on `team`. `PayrollRunViewSet.get_queryset()` only decides which runs a scoped leader reaches (any run with at least one of their team's lines); a run is company-wide, so reaching it must NOT imply seeing every line. `lines()`/`payslip()` re-apply the scope via `_scoped_lines(run)`; `export_excel`/`export_pdf` (one consolidated file) and `period_closure_status` (lists every user) require `_ensure_unrestricted()`; create/update/destroy/finalize/cancel are refused to scoped holders; `PayrollRunSerializer` returns `line_count`/`totals` from the viewer's own lines (`aggregate_line_totals`), and `PayrollRun.notes` is hidden from team scope and not searchable by it. Any new run-level aggregate must be scoped the same way. Real IDOR fixed 2026-09-27; check the same "parent scope is not child scope" pattern wherever a `get_queryset()` gate is followed by a custom `@action` that reaches into related rows. (2) *Drafts cannot finalize on stale inputs (2026-10-18).* `finalize_run` refuses (`_ensure_draft_inputs_current`) when a calculation key of the run's `configuration_snapshot` or any line's wage changed since generation; the admin fix is "Regenerate", never silently freezing old numbers. The TL-gate flag and payslip branding are excluded, branding is read from the snapshot via `run_branding(run)`, and ReportLab `Paragraph` text must go through `_md()` (markup is parsed). A scoped regenerate keeps the snapshot. `PayrollRun.year/month` are read-only. A disabled Payroll plugin is gated in Data Import by `payroll_plugin_disabled()`; finalized-source guards stay `ImportError`-only. Details: `.devin/context/PLUGINS/01-payroll.md`.
- **Reference-table read caching** — `CacheKey.dashboard_reference(list_name, fingerprint)` (`apps/core/cache_constants.py`) + `build_query_fingerprint`/`get_cached_response_data`/`set_cached_response_data` (`core/utils/cache.py`) is the shared pattern for caching a shared (non-user-scoped) list endpoint; it reuses the `v{version}:dashboard:*` namespace so the pre-existing `CacheInvalidationMixin` (already wired into 9 viewsets before any of them actually populated that namespace — dead invalidation until 2026-09-27) invalidates it for free. Check the cache *before* any "ensure singleton exists" `get_or_create` query, not after — otherwise a cache hit still costs a DB query (real bug caught by `GlobalSettingsViewSet`'s own test). A `ReadOnlyModelViewSet` with no API write path (e.g. `DashboardWidgetViewSet`, admin-managed only) uses TTL-only caching, documented inline — don't invent invalidation wiring for a write path that doesn't exist. **Test-cache leakage risk**: Django's test runner never clears `cache` between `TestCase`s (only rolls back DB transactions) — any new test that GETs a cached list endpoint must call `cache.clear()` in `setUp()` itself (see `apps/dashboard/tests/test_reference_cache.py`); there is no global reset hook yet (Phase 6 candidate in `.devin/plans/plan-security-perf-cache-audit-2026-09-27.md`).

Real case: `apps/reports/viewsets.py`'s `CanViewReports.has_permission` caught bare `Exception` around `control_room.services.scope_service.get_access_for_user` and returned `True` (fail-open) on any error; fixed 2026-09-27 to `except ImportError` only, matching the existing narrow pattern in `TeamLeaderFilterMixin` and `PersonalOnlyFilterMixin` in `core/mixins/permissions.py`. See `.devin/plans/plan-security-perf-cache-audit-2026-09-27.md`.

Non-negotiables: (1) Scope is a stored `HbprAlbanianTlAssignment` (one open row per AL TL, evidence-bearing rows never deleted — the PROTECT FK is honoured by filtering, never weakened; evidence-free ended rows older than 6 months are purged by `purge_ended_assignments` — the scheduler does not own it, so it runs lazily in the staff-only list and at boot via `purge_hbpr_archive`; every write goes through `apps/users/services/hbpr_assignments.py`) resolved by `hbpr_scope.py` — never a global population. `effective_to` is the LAST day in effect, not a switch: test openness only through `in_effect_q()`/`unfinished_q()` (`hbpr_assignments.py`), never `effective_to__isnull`. (2) Read-only: the HBPR slice applies to safe methods only; PIP approve/reject and promotion decide are staff/HR-only, evidence is authored by the assigned AL TL only (staff audit, never write), an HBPR exports only evidence of assignments it owns. (3) Employee one-on-ones are unreachable through ANY door: every HBPR-readable scorecard viewset must DECLARE its policy (`HbprScopedQuerysetMixin` raises `TypeError` otherwise), `test_hbpr_invariants.py` walks every route, the scorecard aggregate masks `one_on_one_compliance_pct`. (4) HBPR-only users are denied Calendar, Leave, Organigrama, Skills, Ticket KPI, Engagement, My Records, overtime, standby and reports (manifest `denied_roles`/`denial_override_roles` + `HbprBlockedMixin`; backend `is_hbpr_only` mirrors frontend `isHBPROnly`; multi-role users keep the other role's access). `docker/entrypoint.sh` must keep running `sync_plugins` → `seed_plugin_permissions` → `grant_hbpr_plugin_access` (pinned by `apps/plugins/test_hbpr_boot_path.py`). (5) `hbpr` is a managed role: every admin `roles` list must include it; revoking `hbpr`/`albanian_tl` with an open assignment is a structured 400; a new admin `@action` on `UserViewSet` must join the `IsAdminUser` list in `get_permissions`. (6) Notifications: five `hbpr_*` preference groups (`preference_group`), recipients only from the owner AL TL's open assignment, change detection via `TrackedFieldsMixin` (never a pre_save SELECT). (7) The `/hbpr` workspace pages records and evidence **server-side**: `hbpr/records/` delegates to the resource viewsets — never re-implement scope there; the `kind` vocabulary `pips|promotions|idle|absences|meetings|reviews` is shared with the notification deep links.
- **HBPR schedule edit (2026-10-26)** — the assigned AL TL (and staff) edit the meeting schedule via `POST tl_scorecard/partnership/cadence/`; `can_edit_cadence` is server-decided and the HBPR never writes. History is one `audit_log` row, no notification (follow-up). Shared `CadenceScheduleFields` lives in core `components/hbpr/`. Rules: `docs/hbpr-and-scorecard.md` §Governance evidence and cadence, `docs/workflow-invariants.md` item 34.
- **Search/export must not undo redaction (2026-10-04)** — a `?q=` filter runs in SQL *before* the serializer blanks a field, so searching a redacted column is an oracle (hit/miss reveals hidden text). `HbprScopedQuerysetMixin` therefore splits `search_fields` (visible to everyone in scope) from `private_search_fields` (matched only on rows `own_q` says the viewer owns; staff all) — put any column an `_OwnerOnlyNotesMixin`/`to_representation` blanks (`notes`) in the private list, never the public one. Every CSV/export writer must neutralise free text that starts with `=`, `+`, `-`, `@`, tab or carriage return (prefix `'`): `plugins/tl_scorecard/csv_export._cell` (server) and `records/recordsCsv.ts` (client) — reuse them, don't hand-roll another writer. Pinned by `test_search_cannot_probe_private_notes` and `CsvFormulaSafetyTests`.
- **TL scorecard** — every metric is computed live per month (no snapshot, unlike engagement's `TLApprovalMetric`); `export`/`scorecard` share `build_scorecard`/`governance_records` so evidence exports cannot drift. TL-facing plugins have no admin surface (`/admin/*` is `SuperuserRoute`-gated, so a TL-visible admin-sidebar link is dead). Nobody may decide or approve a record they are part of, staff included. Frontend never statically imports another plugin's module (hit its REST endpoint). `pages/TLScorecardPage.tsx` is orchestration only (sections under `components/scorecard/`); an HBPR-only viewer is redirected to `/hbpr` before any query fires and `viewer.canReview` is `isStaff`. The AL TL's partnership section reads `GET .../partnership/`. A dialog that seeds fields from an `initial` prop must be mounted only while open and keyed (`key={editing?.id ?? "create"}`). The Records tab's table is a preview: `RecordDetailDialog` is the full read view, and it renders only what the **list** serializer already returned (`attendees`, `status_updates` are embedded — opening a record must fire no request), labelling private vs shared text to match the API's redaction instead of re-deriving it. `POST .../idle-status-updates/` (one entry per flag per week) is the only TL-authored child record with a UI; meeting attendees stay read-only (no TL-scoped member picker exists). EPR stage completion is evidence-bearing: `POST .../epr-cycles/{id}/complete_stage/` is the **only** writer of `*_completed_at` (read-only on PATCH, same rule as `Absence.addressed_on`) — it stamps the stage and creates an `EPRStageRecord` (summary required, `reference_url`, `recorded_by`, `shared_with_employee`) atomically; a bare click is not evidence. Workday PDF goal parsing is preview-only through `parse_goal_pdf`; confirmed `goal_titles` may replace goals only at Goal Setting/Mid-year in that same transaction, Final Review rejects them. **Legacy repair (2026-10-08):** a cycle whose Goal Setting is still open after Mid-year/Final was completed (done before the sequence was enforced) is recoverable — `complete_stage`/`parse_goal_pdf` accept `goal_titles` for an *open* Goal Setting even when later stages are done (the Mid-year/Final order guard is unchanged); the UI shows "Repair goals" (`recover` state) instead of a dead "Blocked" row. "Log review" is now "Log management review" (a delivered management review, not EPR; counts toward the 12/year target). Standalone `epr-goals/` is read-only so checkpoints cannot be bypassed. My Records emits `stage_summaries` for shared rows only; the HBPR embed on `EPRCycleSerializer` exposes existence metadata (`has_reference`, `recorded_by_name`), never summary text or the URL — and the standalone `epr-stage-records/` endpoint is `hbpr_no_access` because it serves the full serializer (the embed is the HBPR's only read path). `GET .../hbpr-evidence/year-end-pack/?assignment=&year=` packages held-vs-expected cadence + both EPR participations for the TL's year-end review; it must use `_scoped_queryset` (not `get_queryset`) or the `?year=` `reporting_year` filter drops every `NULL`-year cadence row. **Partnership log (2026-10-08):** the TL view groups the year's evidence into Cadence / Mid-year EPR / Year-end EPR sections (`components/partnership/GroupedEvidenceList.tsx`); the HBPR view is **server-paged**, so it separates types with the `?evidence_kind=` URL param (API `?kind=`, `EvidenceKindFilter`) — never group a single server page client-side (groups split across pages, counts lie). TL-scorecard form dialogs are `size="md"` (512); only confirm prompts stay `sm`. Details: `docs/hbpr-and-scorecard.md`.
- **TL wage visibility** — TLs see their scoreable team's current wage only through `tl_scorecard/team-members/` (D1, 2026-10-11); the payroll `view` grant stays HR-only (HR has parity with staff there, see HR admin-panel isolation); HBPR denied; the wage is `unavailable` while the Payroll plugin is disabled (2026-10-19).
- **Closed year is frozen for everyone (2026-10-26, Y2)** — a `ClosedYear` row freezes that year's overtime and standby: no create, edit, delete, approve or reject for **any** role, superusers included; `manage.py reopen_year --year Y --reason "..."` (audited, reason required) is the only way out. One service (`apps/users/services/approval_periods.py`) owns it; `assert_work_date_open` calls `assert_year_open` first so every serializer inherits it, `MonthlyLockMixin` covers update/delete/approve/reject (`retrieve` stays open — a closed year is still readable), the bulk actions fail the row, both importers return a row error, and `StandbyLogAdmin` refuses the save. **Leave is deliberately exempt** (cancellations flow back into closed balances). The lookup caches 60 s per process (`CLOSED_YEAR_CACHE_TTL_SECONDS`, 0 in e2e); a TestCase that closes a year must `addCleanup(clear_closed_year_cache)`. Details: `docs/workflow-invariants.md` item 31.
- **Year close engine (2026-10-26, Y3)** — `plugins/year_close` builds the frozen evidence set (one ZIP per IT TL/team + `company_{year}.zip` + `{year}/MANIFEST.json`/`.sha256` under `SNAPSHOT_ROOT`). `check_year_readiness` decides; any blocker writes no files and no lock. `ClosedYear` is written **last**, only when every file is ready; `--retry` rebuilds only failed files. Bundles are **disjoint by user** and the completeness gap must be empty, or the build fails — never publish a set that silently drops rows. Pair discovery is batched (`managed_member_ids_bulk`, parity-tested with core); never call `is_team_leader` in a loop. Leave is filtered by overlap. Every Excel sheet title goes through `safe_sheet_title()` (openpyxl raises on `[]:*?/\` and >31 chars, and silently overwrites duplicates). Manifest paths are relative to `SNAPSHOT_ROOT` and stored `.as_posix()`. Details: `docs/workflow-invariants.md` item 32.
- **Previous Years is superuser-only, and the page gates itself (2026-10-26, Y4)** — `/admin/previous-years` is a plugin route inside `SuperuserRoute`, which **also admits staff**, so `PreviousYearsPage` and its sidebar item check `isSuperuser` themselves and the API is `SuperuserOnlyMixin` + `PluginPermissionMixin`. Downloads are `POST files/{id}/download-link/` (120 s token, fresh nonce on the row) then `GET .../download/?token=` (AllowAny, nonce cleared once, `X-Accel-Redirect` to `/_protected/snapshots/`); a failed file answers 409 instead of minting a link. Every download writes an `AuditLog` row. The payroll list defaults its year to `runs/scope/`'s `business_year` (server clock, never the browser), which also fixes the first-50-runs truncation; while that year is unknown the list query is disabled, so render the loading card or every KPI flashes zero. Details: `docs/workflow-invariants.md` item 33.
- **Team lifecycle (2026-10-27)** — rules in `docs/team-lifecycle.md`, summary in `docs/workflow-invariants.md` item 36. Non-negotiables: retire a team by archive (409 on delete with `blockers`); history rows are `SET_NULL` with `team_name`/`team_code` copies and a team-less row is never recomputed; all membership writes go through `change_user_teams` (set diff + history + audit); an archived team confers no TL status; a metrics row is final iff `computed_at >= freeze_at(month)` and scorecard snapshots are written by the job, never on read; workspaces of a deleted team are detached, never deleted.

## Verification Commands

Targeted while iterating; the full pass exactly once, after implementation.

```bash
# Iterating — narrow the path, never the whole suite
py -3.14 manage.py check
py -3.14 manage.py test apps.<app>.tests.<name>
cd frontend && npx vitest run src/<path> && npx eslint src/<path>

# Full pass, once at the end
py -3.14 manage.py makemigrations --check && py -3.14 manage.py test
python -m ruff check --output-format=concise <changed .py files>
cd frontend && npx tsc --noEmit && npx vitest run && npm run build
```

Dev uses `py -3.14`; the production image and CI run Python 3.12 + Django 6.1.1. The default `python` is 3.11 + Django 5.2 and hides Django-6 differences, so use `py -3.14` for Django commands.

## graphify

This project has a knowledge graph at graphify-out/ with god nodes, community structure, and cross-file relationships.

Rules:
- For codebase questions, first run `graphify query "<question>"` when graphify-out/graph.json exists. Use `graphify path "<A>" "<B>"` for relationships and `graphify explain "<concept>"` for focused concepts. These return a scoped subgraph, usually much smaller than GRAPH_REPORT.md or raw grep output.
- If graphify-out/wiki/index.md exists, use it for broad navigation instead of raw source browsing.
- Read graphify-out/GRAPH_REPORT.md only for broad architecture review or when query/path/explain do not surface enough context.
- After modifying code, run `graphify update .` to keep the graph current (AST-only, no API cost).
